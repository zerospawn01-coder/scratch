# 『CRISIS ACTOR』EP3「超外神殻」一人回し検証ログ

## 概要
- **検証日**: 2026-06-25
- **検証環境**: Godot VTT (v4.6.3-stable / 4.7 互換確認済み)
- **セッション構成**: GM 1名 + PL 4名（PC1: ディレクター, PC2: オーディター, PC3: エンジニア, PC4: キャストマネージャー）
- **検証目的**:
  1. 行政ホラーの演出システム（文化財化処理クロック、三種の行政文書、禁止語・代替語、黒塗り理由コード）の実用性検証。
  2. VTTの操作性（カード管理、スクロール、検索機能）がセッションのテンポを阻害しないかの確認。

## タイムライン & シーン検証

### Phase 1: ロケハン — 「再現される住民」
- **想定進行**:
  - 帳ノ沢村に入り、開発PR用のインタビュー撮影を開始。
  - 出演住民の多くが県手配の役者（サクラ）であることに気づく。のぞみが「村人はサクラ」とSNSに比較画像を投稿し炎上。
- **発生する判定**:
  - PC4: 〈演出〉または〈精神〉判定による「エキストラ住民の動揺抑制」
  - PC1: 〈脚本〉または〈演出〉判定による「PR撮影の進行と代役処理の決定」
- **使用カード**:
  - 初期白カード: 「帳ノ沢村の住民移転は、県と住民の合意に基づき円満に進行している」
  - 初期灰カード: 「名簿の不一致」【腐爛0】
  - 発生灰カード: 「エキストラ代役の混入」【腐爛0】（PC4の判定失敗により発生）
  - 発生疑惑カード: 「帳ノ沢村は県が作った観光用セットである」
- **GM操作 (VTT)**:
  - 検索欄で「名簿の不一致」を検索、PC2が `Witness Claim` を宣言するにあたり、TOCから「3. システムとカードルール」へジャンプ。
  - クロック管理: のぞみのSNS炎上（一次データ）を放置したため、フェーズ終了時に `文化財化処理クロック` を 0 -> 1 に進める。
- **詰まりそうな点 / 改善案**:
  - **PC4のジレンマの重さ**: 本物の住民の声を代役トーンに揃える処理が、プレイヤーに心理的抵抗を生む。GMは「これで公式ログとしては美しくなります」と冷淡に案内すること。
  - **VTT操作**: 疑惑カードを追加した際、リストが長くなると見失いそうになるが、今回実装した「最下部への自動スクロール」のおかげで、入力後のスクロールの手間が省けスムーズになった。

### Phase 2: 帳外神楽 — 「避難経路の詞章」
- **想定進行**:
  - 神社で神楽の撮影。歌詞が「30年前の避難経路」のログになっていることをPC2が地図と照合して特定。
  - ミトが「名簿にない者から、先に橋を通せ」と台本外のセリフを言う。
- **発生する判定**:
  - PC2: 〈情報〉判定による「古地図と歌詞の照合」（難易度2）
  - PC3: 〈演出〉判定による「セリフ部分の音声カット/編集」
- **使用カード**:
  - 発生灰カード（祭文カード）: 「神楽の歌詞に隠された避難経路」
  - 処理: PC3が「迷信として編集でカットする」を選択。
  - 影響: 監査負債+1、粗い演出カード「消えた一節」が発生。
- **GM操作 (VTT)**:
  - `監査負債` を1から2にインクリメント。
  - カード追加機能で、粗い演出カード「消えた一節」を追加。
  - クロック管理: 祭文カードのカットおよび放置に伴い、`文化財化処理クロック` を 1 -> 2 へ進める。
- **詰まりそうな点 / 改善案**:
  - プレイヤーが「歌詞に何が書かれているか」を検索したい場合、VTTの検索窓で「避難経路」や「帳外帳」で引く。検索結果が即時反映されるため、GMが説明をモタつかずに済んだ。
  - 「消えた一節」という粗い演出カードが発生したことで、PC3（エンジニア）は「将来のリスク（着服の監査防止）」の勝利条件に一歩近づくが、PC1は監査負債が増えたため焦り始める。

### Phase 3: 禁足地ロケ — 「未分類フレーム」
- **想定進行**:
  - 禁足地でのドローン空撮。「第4避難誘導実験区域」の錆びた看板を発見。
  - 機材センサーに謎のデジタルノイズ（異物フレーム）が発生。
- **発生する判定**:
  - PC3: 〈情報〉または〈演出〉判定による「ノイズの解析と除去」
  - PC4: 〈精神〉判定による「村人の人為的配置の聞き取り」
- **使用カード**:
  - 発生灰カード: 「神楽映像の端に子ども用の面が数フレームだけ映っている」
  - 処理: PC3が「機材ノイズとして処理（B級処理）」を宣言。
  - 影響: `文化財化処理クロック`+1、粗い演出カード「機材異常の言い訳」が発生。PC3の機材劣化クロック+1。
- **GM操作 (VTT)**:
  - `現実混入率` は動かさず、`文化財化処理クロック` を 2 -> 3 に進める。
  - カードリストに「機材異常の言い訳」を追加。
- **詰まりそうな点 / 改善案**:
  - **B級処理のテンポ**: 判定難易度を下げる代わりに「粗い演出カード」がどんどん場に増え、ログが汚れていく。「後始末を誰がするのか」でPL間で押し付け合いが発生しやすい。
  - **ノイズ・レキシコンの適用**: 混入率3〜4段階のGM描写（「波形が不自然です」）を会話に差し挟むことで、プレイヤーに「システムが歪み始めている」感覚を効果的に与えられた。

### Phase 4: クライマックス — 「帳外帳の処理」
- **想定進行**:
  - 帳外帳を発見。A・B・Cいずれのエンドに進むかの合意形成ラウンド。
  - PC1が「白カード化（完全偽装）」を強行（PC2は反発するが、PC1が『強行決定』を使用し却下）。
- **使用カード**:
  - 処理: 選択肢A「民俗文化として白カード化する」の実行。
- **GM操作 (VTT)**:
  - 登録票テンプレートとPRナレーション原稿をプレイヤーに開示（VTTのドキュメントビューアをEP3の§9にフォーカスさせる）。
  - プレイヤーがフォームの穴埋めと、PR原稿の書き換え（「避難経路」の消去）を行う。
  - クロックは最終的に段階6「文化財化完了」に達し、黒カードを白カードに吸収・消滅させる。
  - `監査負債` を+2（トータル4へ）。
  - `セッション保存` を押し、`user://session_log.json` を出力。
  - `Markdown書き出し` を押し、`user://session_log.md` を保存。

## パラメータ・クロック挙動の検証評価

### 1. 文化財化処理クロック (0〜6) の機能性
- **評価: 極めて優秀。**
- プレイヤーが議論で停滞した際や、臭いものに蓋（カット、ノイズ処理）をするたびに機械的に上昇する。
- 段階4「個人名削除」、段階5「解説文確定」と段階が進むアナウンスをGMが行うことで、「システムによって自動的に歴史が綺麗にされていく」という焦燥感をPLに強く与えられた。
- 段階6の「黒カード1枚を白カードへ吸収する」ルールにより、PC2（オーディター）が命がけで確保した証拠が「無害な美しい資料」に変換されてしまうため、クライマックスの行動を急がせる動機として完璧に機能している。

### 2. 登録票 / PRナレーション / 完了報告書の手触り
- **評価: 「悪意なき加害（白カード化）」の体験として成功している。**
- **登録票**: 「人災」「隠蔽」などの告発用の欄がなく、プレイヤーは「地域信仰」や「災害記憶」にチェックを入れざるを得ない。
- **PRナレーション**: 元の詞章「七つ目の石を踏んだら立ち止まれ。戻らぬ橋の手前で、南の窪地を探せ」を「祈りの道しるべ」「聖域との境界線」にプレイヤー自身の手で書き換えさせる儀式は、心理的抵抗が非常に大きい。
- **完了報告書メール**: 「住民説明会における情緒的反応も、映像資料の補助によっておおむね沈静化」という県からの無機質なテキストが送られてきた瞬間、PL全員が「私たちは最悪の片棒を担いだ」と実感できる。

## 卓中操作性（VTT）の検証と改善点

### 1. 検索・TOC・カード管理の操作感
- 検索UIは非常に使いやすい。特に「黒塗り理由」「文化財化処理」などのクイック検索ボタンにより、ルールやテーブルの確認が瞬時に行える。
- **改善された点**:
  - 先ほど実装した「カード追加時の自動スクロール」により、セッション中に白・灰・黒カードを連続で発行するGMの負担が大幅に軽減された。スクロールを手動で下げる必要がないため、ゲームのテンポを落とさずに描写に集中できる。
  - メッセージ一時表示の世代管理（`_msg_generation`）により、セッション保存やエクスポートをPLに確認しながら連打しても通知表示が壊れなくなった。

### 2. 発生した「実卓上の詰まりどころ（P1修正候補）」
1. **代替語置換時のPLの思考ロック**:
   - クライマックスの執筆時、禁止語（災害、隠蔽など）に引っかからないようにPLが悩みすぎて沈黙してしまう。
   - *対策*: VTT画面の「クイック検索」欄に「禁止語テーブル」への直接リンクボタン、または別窓で常に禁止語リストを表示できると親切。
2. **PCごとの勝利条件の衝突**:
   - PC1（監査負債2以下で白カード固定）とPC3（粗い演出カードが残る）の利害対立が激しいため、Aエンドの合意形成で揉めやすい。
   - *対策*: ルールブックに「異議申立ラウンド」の制限時間ルールを設けるべき（議論は最長5分とし、決着しなければPC1の『強行決定』か、ダイス勝負で決める）。
3. **セッション保存時の出力確認**:
   - セッション保存完了時、「user://session_log.md に保存しました」と表示されるが、GMがPC上のどこに保存されたか一瞬迷う。
   - *対策*: アプリのヘルプや設定欄に「保存フォルダ（AppData配下のGodotユーザディレクトリ）を開く」ボタンがあるとより親切。
