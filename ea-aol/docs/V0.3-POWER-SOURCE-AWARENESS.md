# EA-AOL v0.3: Power Source Awareness

**"OSのエコモードを捨てろ。EA-AOLを入れろ。"**

## 🎯 核心的な違い

### 従来のOS（Windows/Linux）
```
省電力モード = CPU/GPU周波数を下げる
結果: AIが遅くなる → 使い物にならない
```

### EA-AOL v0.3
```
省電力モード = 計算量そのものを減らす
結果: AIは速いまま → 品質が少し下がるだけ
```

## 🏗️ アーキテクチャ

### 3つの電源状態

```c
typedef enum {
    EA_POWER_GRID = 0,      // AC電源（無制限）
    EA_POWER_BATTERY,       // バッテリー（制限あり）
    EA_POWER_CRITICAL       // バッテリー危機（<20%）
} ea_power_state_t;
```

### 3つの戦略

| 状態 | 戦略 | Top-K | 目的 |
|------|------|-------|------|
| **GRID** | Performance | 100% (8/8) | 最高品質 |
| **BATTERY** | Balanced | 50% (4/8) | 品質と持続時間のバランス |
| **CRITICAL** | Survival | 最小 (1/8) | とにかく生き延びる |

## 💡 実装の核心

### Linux実装（sysfs）

```c
ea_power_state_t ea_hal_get_power_state(void) {
    // AC電源チェック
    FILE* fp = fopen("/sys/class/power_supply/AC/online", "r");
    int ac_online = 0;
    fscanf(fp, "%d", &ac_online);
    fclose(fp);
    
    if (ac_online) return EA_POWER_GRID;
    
    // バッテリー残量チェック
    fp = fopen("/sys/class/power_supply/BAT0/capacity", "r");
    int capacity = 0;
    fscanf(fp, "%d", &capacity);
    fclose(fp);
    
    if (capacity < 20) return EA_POWER_CRITICAL;
    return EA_POWER_BATTERY;
}
```

### Top-K自動調整

```c
uint32_t ea_hal_adjust_topk_for_power(uint32_t base_k) {
    ea_power_state_t state = ea_hal_get_power_state();
    
    switch (state) {
        case EA_POWER_GRID:     return base_k;           // 100%
        case EA_POWER_BATTERY:  return (base_k + 1) / 2; // 50%
        case EA_POWER_CRITICAL: return 1;                // 最小
    }
}
```

## 🚀 市場への影響

### 1. AI PC / ラップトップ
**問題**: Microsoft Copilot+ PCは、バッテリー駆動時にAI性能が大幅低下  
**EA-AOL**: バッテリーでもサクサク動く

### 2. ドローン / ロボット
**問題**: バッテリー切れ = 墜落  
**EA-AOL**: 「帰還する分のバッテリーを残すために、認識精度を落とす」判断が可能

### 3. 災害用AI
**問題**: 停電した避難所での発電機燃料節約  
**EA-AOL**: 燃料を節約しながらAIを稼働

### 4. データセンター
**問題**: グリーン電力（太陽光）が不足する夜間  
**EA-AOL**: 電力源に応じて自動的に品質調整
